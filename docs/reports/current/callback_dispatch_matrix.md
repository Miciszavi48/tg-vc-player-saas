# Callback dispatch matrix — project-wide audit summary

Generated by `scripts/audit_callback_dispatch_matrix.py` (companion machine-readable
inventory: `callback_dispatch_matrix.json`, same directory). JSON regenerated
against current source on 2026-07-19. This Markdown summary is maintained
manually because the generator emits JSON only.

## What the matrix probes

Every representative callback sample (static keyboard emissions, curated dynamic
payloads, and CB-constant surfaces — 1014 samples over 521 registered callback
handlers) is replayed through faithful Kurigram group-ordered dispatch with real
filter evaluation, across three probes:

| probe | actor | query |
|---|---|---|
| `fresh_allowed` | developer | fresh message, correct chat scope |
| `stale_allowed` | developer | `query.message is None` (old/edited/deleted panel) |
| `fresh_denied` | non-developer outsider | fresh message, correct chat scope |

Plus: full acceptor sets per sample (duplicate-ownership/shadowing detection),
`_KNOWN_CB_PREFIX` family coverage, and pattern-less handler detection.

The registry pass also inventories 87 `MessageHandler`s and one filterless
`RawUpdateHandler`. A private Developer proxy-input probe replays the first
claimant in every group: language message binder (`-1000`), global-ban message
guard (`-995`), call-security raw observer (`-900`), OTP text listener (`-90`),
helper proxy listener (`-89`), then broadcast schedule/payload listeners
(`-85`/`-80`). It has zero defects and proves the raw observer cannot block
typed messages and OTP/proxy no longer share a group.

## Informational (verified as designed, not defects)

- `stale_reopen_menu_ux` (595): deep action/toggle/confirm callbacks answer the
  "reopen the menu" alert on stale taps — designed UX (the
  `common.errors.unknown_callback` copy is worded for exactly this case).
- `stale_explicit_rejection` (117): stale taps that reach an explicit family
  deny/malformed rejection handler.
- `denied_private_forged_tap_unknown` (552): private dev/owner panel identities
  tapped by outsiders (only possible via forged/stale buttons) answer the
  unknown alert — acceptable.
- `duplicate_same_module_chain` (80): help_center legacy chain and dev_panel
  removed-financial rejection surface — deliberate registration-order chains.
- `duplicate_intentional_dev_shortcut` (9): documented dev-panel shortcut
  handlers sharing render helpers with the canonical owner.

## Intentionally obsolete surfaces
